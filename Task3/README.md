## Обоснование изменений
- Внедрение Kubernetes и Kafka позволит решить проблемы с масштабируемостью системы и уменьшить риск отказа при увеличении объёма данных.
- Создание нового приложения для операторов необходимо для упрощения работы операторов в Data Lake. Он заменит устаревшее приложение Power Builder. Позволит эффективнее работать с данными и улучшит пользовательский опыт.
- Замена старого DWH на основе MS-SQL сервер на Data Lake позволит сэкономить деньги на лицензии. MS-SQL сервер плохо масштабируется.
- Внедрение концепции Data Mesh позволит интегрировать новые домены без значительных изменений DWH. Это повысит качество данных, следовательно улучшит аналитику данных. Позволит развивать продукты независимо, сокращая накладные расходы на коммуникацию.
- Внедрение Greenplum в качестве витрины данных позволит ускорить построение отчётов. Это снизит риски ухудшения производительности после интеграций новых бизнес доменов.
- Использование Data Lake повысит эффективность работы ИИ домена, так как задуман для работы с неструктурированными данными.
- Создание программы обучения сотрудников, включая пример реализации пайплайна, позволит значительно ускорить подключение доменов к новой инфраструктуре, уменьшит количество ошибок, а также снизит стоимость поддержки в будущем.
